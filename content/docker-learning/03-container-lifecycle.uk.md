# Життєвий цикл контейнера та процеси

## Результати

Створюйте, запускайте, досліджуйте й видаляйте контейнери, не плутаючи їх з образами. Розумійте коди завершення, сигнали, PID 1, стан здоров’я та політики перезапуску.

## Стани та команди

| Команда | Дія |
| --- | --- |
| `docker run` | Створює новий контейнер і запускає його |
| `docker start` | Запускає наявний зупинений контейнер зі збереженою конфігурацією |
| `docker stop` | Надсилає сигнал зупинки, після таймауту примусово завершує процес |
| `docker restart` | Зупиняє та запускає наявний контейнер |
| `docker rm` | Видаляє контейнер і його записуваний шар |
| `docker exec` | Запускає додатковий процес у працюючому контейнері |

Зміна змінної середовища у вашому shell не змінює наявний контейнер. Створіть його заново з потрібними параметрами. Перезапуск не є збиранням образу, а збирання не замінює працюючий контейнер.

## Дослідження перед змінами

```sh
docker run -d --name lifecycle-demo python:3.13-slim python -m http.server 8000
docker ps -a
docker inspect --format '{{json .State}}' lifecycle-demo
docker top lifecycle-demo
docker logs --tail 30 lifecycle-demo
docker exec lifecycle-demo python -c "import os; print(os.getpid())"
docker stop --timeout 10 lifecycle-demo
docker inspect --format '{{.State.ExitCode}}' lifecycle-demo
docker rm lifecycle-demo
```

Для `exec` потрібні працюючий контейнер і програма, наявна в образі. Мінімальні образи можуть не мати `bash` або `curl`. Додатковий процес `exec` не є початковим процесом сервісу.

## PID 1 та коректна зупинка

Docker стежить за головним процесом контейнера. Exec-форма `CMD ["python", "app.py"]` не додає зайвий shell. Скрипт-обгортка має використовувати `exec` для передавання керування застосунку, щоб сигнали доходили до нього. Застосунок повинен обробляти зупинку та завершувати або скасовувати роботу за відведений час.

Init-процес, увімкнений через `--init` або Compose `init: true`, допомагає передавати сигнали й прибирати завершені дочірні процеси. Він не забезпечує коректну обробку транзакцій замість застосунку. Перевіряйте зупинку через SIGTERM, код завершення та збережені дані.

## Працює, здоровий і готовий

Running означає, що головний процес не завершився. Docker health check — окрема команда зі станом успіху або помилки. Готовність має відображати здатність виконати потрібну операцію: процес може працювати без доступу до бази.

Сам стан unhealthy не змушує Docker Engine перезапускати окремий контейнер. Політика перезапуску реагує на завершення процесу відповідно до своїх правил. Умови здоров’я залежностей Compose керують порядком запуску, але не відновлюють постійно всі залежні сервіси.

## Коди завершення та очищення

Код 0 зазвичай означає успішне завершення; ненульовий код визначає помилку конкретної програми. Код 137 може бути наслідком SIGKILL, зокрема через OOM, але сам по собі не доводить нестачу пам’яті. Перевірте `.State.OOMKilled`, події демона й метрики хоста.

Видаляйте навчальний контейнер за назвою. Загальні prune-команди зачіпають інші проєкти того самого демона. Перед очищенням дослідіть `docker system df` і належність ресурсів; глобальне видалення не є звичайним способом діагностики.

## Контрольне запитання та відповідь

**Запитання:** Контейнер unhealthy, має `restart: unless-stopped`, але продовжує працювати. Політика зламалася?

**Відповідь:** Ні. Головний процес не завершився. Стан здоров’я і причина перезапуску — різні речі. Дослідіть перевірку та поведінку застосунку; визначте, чи він має завершитися, самостійно відновитися або працювати під керуванням оркестратора.

## Підсумок

Читайте стан і журнали перед перезапуском. Для зміни конфігурації замінюйте контейнер, а коректну зупинку перевіряйте окремо.
