# Сховища, права та резервні копії

## Результати

Обирайте відповідне сховище, пояснюйте збереження чи втрату даних і відрізняйте постійний том від перевіреної резервної копії.

## Варіанти сховища

| Тип | Застосування | Життєвий цикл і ризик |
| --- | --- | --- |
| Записуваний шар контейнера | Тимчасові робочі файли | Видаляється разом із контейнером |
| Іменований том | Дані застосунку під керуванням Docker | Переживає заміну контейнера, але залежить від хоста і сховища |
| Bind mount | Локальний код або явно керовані файли хоста | Залежить від шляху та прав на машині демона |
| tmpfs | Тимчасові робочі дані | Зникає після зупинки; дані з пам’яті можуть потрапляти у swap |

У Desktop іменовані томи обслуговуються всередині Linux VM. Bind mount посилається на машину демона, не обов’язково на машину CLI. Копіювання внутрішніх директорій Docker не є стратегією резервування застосунку.

## Експеримент зі збереженням

```sh
docker volume create docker-course-data
docker run --rm --mount type=volume,src=docker-course-data,dst=/data python:3.13-slim python -c "from pathlib import Path; Path('/data/message').write_text('survives replacement')"
docker run --rm --mount type=volume,src=docker-course-data,dst=/data,readonly python:3.13-slim python -c "from pathlib import Path; print(Path('/data/message').read_text())"
docker volume inspect docker-course-data
```

Другий, новостворений контейнер має прочитати повідомлення. `--rm` видалив перший контейнер, але не іменований том. Після завершення, якщо навчальні дані більше не потрібні, видаліть саме цей том через `docker volume rm docker-course-data`.

## Монтування приховує наявні шляхи

Bind mount поверх `/app` приховує вміст `/app` з образу на час монтування. Новий порожній том може отримати початкові файли з цільового шляху; наявний заповнений том зберігає власний вміст. Перебудова образу не переписує дані наявного тому застосунку.

Це пояснює зникнення залежностей під монтуванням коду та застарілу конфігурацію в повторно використаних томах. Дослідіть монтування перед пошуком помилки в COPY.

## UID та директорії для запису

Права Linux використовують числові UID/GID. Користувачеві 10001 потрібен доступ до директорій даних. Проєкт створює `/data` з відповідним власником до підключення нового тому. Наявні томи чи довільні bind mount можуть мати іншого власника.

Не використовуйте `chmod -R 777` як універсальне рішення. Визначте шлях, UID контейнера, власника на хості, режим read-only і можливу політику SELinux. Змінюйте лише потрібний ресурс. Коренева файлова система лише для читання сумісна з явно доступними для запису томами й tmpfs.

## Резервування та відновлення

Том забезпечує збереження, але не резервну копію. Визначте допустиму втрату даних (RPO) і час відновлення (RTO), створюйте узгоджену з застосунком копію, зберігайте її поза тією самою зоною відмови та тренуйте відновлення в інший том.

Для невеликої SQLite-бази проєкту використовуйте backup API SQLite, потім скопіюйте завершену копію з контейнера:

```sh
docker compose exec api python -c "import sqlite3; source=sqlite3.connect('/data/counter.sqlite'); target=sqlite3.connect('/tmp/counter-backup.sqlite'); source.backup(target); target.close(); source.close()"
docker compose cp api:/tmp/counter-backup.sqlite ./counter-backup.sqlite
```

Виконуйте в `examples/docker-learning` після запуску. Перевірте файл через SQLite, відновіть його в окремий тестовий том і перевірте лічильник через API. Архівування директорії працюючої бази не гарантує узгодженості транзакцій. Для інших баз потрібні їхні процедури дампів або знімків.

## Контрольне запитання та відповідь

**Запитання:** `docker compose down --volumes` — це просто зупинка застосунку?

**Відповідь:** Ні. `down` прибирає контейнери й мережі стека; `--volumes` також видаляє оголошені не зовнішні іменовані томи та підключені анонімні томи. Це навмисне видалення постійних даних проєкту. Використовуйте лише для непотрібних або відновлюваних даних.

## Підсумок

Документуйте власника сховища, поведінку після заміни та процедури відновлення. Перевіряйте відновлення, а не саму наявність файлів копій.
