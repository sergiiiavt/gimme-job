# Налаштування та перший запуск

## Результати

Встановіть підтримуване середовище Docker, відрізніть працездатний клієнт від запущеного демона та запустіть сервіс, доступний із хоста. Використовуйте офіційну інструкцію для своєї ОС замість неперевіреного інсталяційного скрипту.

## Вибір платформи

| Хост | З чого почати | Важлива відмінність |
| --- | --- | --- |
| Mac з Apple silicon | Docker Desktop для Apple silicon | Обирайте Linux ARM64; x86-образам може знадобитися емуляція |
| Mac з Intel | Docker Desktop для Intel | Інсталятор має відповідати процесору |
| Windows | Docker Desktop з підтримуваним WSL 2 | Linux- і Windows-контейнери мають різні ядра й образи |
| Linux | Docker Engine і плагін Compose | Виконуйте інструкцію для конкретного дистрибутива |

На робочому ноутбуці використовуйте погоджений спосіб встановлення та перевіряйте умови ліцензування Desktop. Engine, Desktop і підписка на реєстр — різні продукти. Не фіксуйте ціни чи системні вимоги в інсталяційному скрипті: звіряйтеся з актуальними офіційними вимогами.

## Перевірка клієнта, сервера та плагінів

```sh
docker version
docker info
docker compose version
docker buildx version
docker context ls
docker context show
```

`docker version` має показати Client і Server. Якщо є лише Client та помилка з’єднання, самого CLI недостатньо. Запустіть Desktop або демон Linux і перевірте вибраний контекст. Контекст може вказувати на іншу машину: команди змінюють контейнери, сховища й порти саме її демона.

## Перший короткочасний контейнер

```sh
docker run --rm hello-world
docker ps
docker ps -a
docker image ls
```

Процес привітання успішно завершується. Через `--rm` контейнер видаляється, тому `docker ps` може нічого не показати. Образ залишається локально. У корпоративній мережі для доступу до реєстру можуть знадобитися погоджені проксі та довірений CA; не вимикайте перевірку TLS заради обходу проблеми.

## Перший локальний сервіс

```sh
docker run -d --name docker-course-web -p 127.0.0.1:18080:8000 python:3.13-slim python -m http.server 8000
curl --fail http://127.0.0.1:18080/
docker logs --tail 20 docker-course-web
docker stop docker-course-web
docker rm docker-course-web
```

Очікуйте HTTP-список файлів, потім зупинений і видалений контейнер. Прив’язка до loopback залишає вправу локальною для хоста. Якщо порт 18080 зайнятий, змініть порт хоста; порт контейнера залиште 8000. Цей Python HTTP-сервер призначений лише для локальної вправи без конфіденційних файлів.

## Права доступу та діагностика

На Linux членство в групі `docker` дає потужний контроль над демоном, зазвичай еквівалентний root-доступу до хоста. Rootless mode — окремий варіант зі своїми вимогами й обмеженнями. Не виправляйте права socket командою `chmod 666`.

У Desktop образи та іменовані томи зберігаються в керованому сховищі Linux VM. Відсутність папки у Finder не означає втрату тому. Для віддаленого контексту `127.0.0.1` у прив’язці опублікованого порту означає віддалений хост.

## Контрольне запитання та відповідь

**Запитання:** `docker --version` працює, але `docker run hello-world` не підключається. Що перевірити спочатку?

**Відповідь:** Переконайтеся, що демон запущений, перегляньте `docker context show` і `docker context ls`, потім перевірте доступ до цієї кінцевої точки. Версія CLI підтверджує лише наявність програми. Перевстановлення залежностей застосунку не відновить зв’язок із демоном.

## Підсумок

Явно визначайте клієнт, демон, контекст, архітектуру та порт хоста. Переходьте далі після успішного короткого запуску й перевірки доступного локального сервісу.
