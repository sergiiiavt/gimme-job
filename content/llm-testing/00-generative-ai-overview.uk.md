# Генеративний AI та LLM: вступ

Генеративний AI охоплює більше, ніж чатботи. Велика мовна модель (LLM) — один із компонентів продукту. Почнімо з основних понять, архітектури систем і структури навчання. Попередній досвід тестування або роботи з AI не потрібний.

**Передумови:** немає.

## AI, ML, генеративний AI та LLM

Штучний інтелект (AI) — загальна назва систем, які виконують завдання, пов’язані з інтелектуальною діяльністю людини. Частина систем працює за явними правилами. Машинне навчання (ML) виявляє закономірності в даних. Глибоке навчання використовує багатошарові нейронні мережі. Трансформер — архітектура, на якій побудовано багато сучасних мовних моделей.

Генеративний AI створює текст, код, зображення, аудіо або відео. LLM орієнтована передусім на мову; її часто навчають передбачати наступний токен у послідовності. Класифікатор спаму може використовувати ML без генерації вмісту. Генератор зображень не обов’язково є LLM. Мультимодальні моделі працюють із кількома видами даних.

| Поняття | Основне призначення | Приклад |
|---|---|---|
| Штучний інтелект | Виконувати інтелектуальні завдання | Планування та рекомендації |
| Машинне навчання | Виявляти закономірності на прикладах | Виявлення шахрайства |
| Глибоке навчання | Навчати нейромережі подань даних | Розпізнавання мовлення |
| Генеративний AI | Створювати новий вміст | Генерація тексту чи зображення |
| Велика мовна модель | Обробляти й генерувати послідовності токенів | Відповісти на запитання або пояснити код |

Ці категорії перетинаються. Можна створити функцію AI без LLM або вбудувати LLM у звичайний застосунок.

## Як мовна модель створює відповідь

Токенізатор перетворює текст на токени. Модель обробляє послідовність і обчислює оцінки можливих наступних токенів. Алгоритм декодування вибирає наступний токен; процес повторюється до умови завершення. Це не пошук готового речення в базі даних. Наступний розділ пояснює токенізацію, механізм уваги, вибір токенів і навчання.

Попереднє навчання допомагає засвоїти широкі статистичні закономірності. Налаштування на інструкціях і оптимізація за вподобаннями можуть зробити модель кориснішою, але не гарантують достовірності фактів чи міркувань. Переконлива відповідь не доводить, що модель перевірила джерело, виконала обчислення або здійснила дію. Для зовнішньої інформації та дій потрібні інші компоненти застосунку.

Під час вибору моделі враховуйте розмір контексту, види даних, затримку, вартість, підтримку мов, правила обробки даних, спосіб розгортання та якість потрібного завдання.

## Модель, застосунок і продукт

Модель має навчені ваги, логіку обчислення та інтерфейс вхідних і вихідних даних. Застосунок поєднує промпти, історію розмови, знайдену інформацію, інструменти, перевірки та бізнес-правила. Продукт також потребує автентифікації, зручного інтерфейсу, відгуків, моніторингу й відповідальної експлуатації.

Шлях запиту до помічника служби підтримки:

| Крок | Компонент | Відповідальність |
|---|---|---|
| 1 | API застосунку | Перевірити права користувача та вхідні дані |
| 2 | Оркестратор | Зібрати інструкції й релевантний контекст |
| 3 | Компонент пошуку | Знайти актуальні документи, які користувач має право читати |
| 4 | LLM | Створити відповідь або структурований запит на виклик інструмента |
| 5 | Виконавець інструментів | Перевірити дозвіл і виконати зовнішню дію |
| 6 | Обробка результату | Перевірити й показати відповідь, підтримати потокове передавання та записати використання ресурсів |

Модель сама не встановлює права доступу до замовлення й не підтверджує фактичне повернення коштів. Застосунок перевіряє дозволи та результати зовнішніх операцій. Промпт не є межею безпеки.

## Поширені способи побудови систем

| Підхід | Типове завдання | Що перевірити |
|---|---|---|
| Прямий промпт | Узагальнити наданий документ | Межі контексту й точність |
| Структурована генерація | Витягнути запис у JSON | Схему та відсутні поля |
| Генерація з доповненням результатами пошуку — RAG | Відповісти на основі актуальних правил | Якість пошуку, актуальність і контроль доступу |
| Виклик інструментів | Перевірити доступне користувачу замовлення | Серверні дозволи й обробку помилок |
| Агент | Виконати багатокроковий процес | Погодження дій, цикли, вартість і трасування |
| Донавчання | Адаптувати модель на спеціалізованих прикладах | Навчальні дані, оцінювання й супровід |

RAG додає зовнішню інформацію під час запиту без оновлення ваг моделі. Донавчання змінює модель на навчальних прикладах. Агент — спосіб побудови застосунку з циклом вибору дій. Структурована відповідь полегшує програмний розбір, але не гарантує правдивості вмісту.

## Базовий словник

Назви в документації різних постачальників можуть відрізнятися. Англійські відповідники допоможуть зіставити терміни.

| Термін | Значення |
|---|---|
| Базова модель — foundation model | Модель, навчена на широких даних для різних завдань |
| Ваги — model weights | Навчені параметри нейромережі |
| Обчислення моделлю — inference | Застосування навченої моделі до вхідних даних |
| Токен і токенізатор | Одиниця послідовності та компонент, який перетворює текст на ідентифікатори токенів |
| Контекстне вікно | Максимальна послідовність токенів, включно з історією та доданими матеріалами |
| Промпт | Вхідні дані й інструкції для моделі |
| Ролі повідомлень | Ролі system, developer, user тощо; підтримка залежить від постачальника |
| Вибір токенів і температура | Механізм вибору наступного токена та параметр, який впливає на варіативність |
| Векторне подання — embedding | Числове подання для порівняння подібності та пошуку |
| Пошук — retrieval | Відбір релевантної зовнішньої інформації |
| RAG | Додавання знайдених матеріалів до запиту моделі |
| Виклик інструмента — tool call | Структурований запит моделі до застосунку на виконання функції |
| Агент | Цикл застосунку, який вибирає дії та використовує інструменти |
| Мультимодальність | Робота з кількома видами даних |
| Опора на джерела — grounding | Зв’язок відповіді з наданими доказами |
| Галюцинація | Правдоподібний, але не підтверджений фактами чи джерелами вміст |
| Захисний механізм — guardrail | Контроль, який обмежує, перевіряє або блокує вхідні чи вихідні дані |
| Затримка й вартість токенів | Час відповіді та ресурси, потрібні для запиту |

### Терміни оцінювання

Оцінювання й тестування LLM вивчаємо після основ. Словник допоможе читати матеріали вже зараз. У різних інструментах терміни вживають непослідовно; у курсі вони мають наведені нижче значення.

| Термін | Значення в курсі |
|---|---|
| Оцінювання — evaluation, eval | Повторюване вимірювання якості: набір даних, запуск системи, оцінювачі та правило рішення |
| Приклад — case, sample | Вхідні дані для оцінювання; можуть мати еталонну відповідь, метадані й теги |
| Набір даних — dataset | Версіонована сукупність прикладів; golden dataset — ретельно відібраний довірений набір |
| Оцінювач — scorer, grader | Код, модель або людина, що присвоює оцінку чи вердикт |
| Метрика | Узагальнення оцінок, наприклад частка успіху або середня відповідність джерелам |
| Модель-оцінювач — judge | LLM, яку використовують для оцінювання |
| Рубрика | Письмові критерії для людини або моделі-оцінювача |
| Еталонна відповідь | Відомий прийнятний результат або обов’язкові факти |
| Базовий рівень — baseline | Результат чинної версії для порівняння |
| Регресія | Статистично й практично значуще погіршення проти базового рівня |
| Трасування й окрема операція — trace, span | Запис обробки запиту та кроків: виклик моделі, пошук, виклик інструмента |
| Галюцинація — hallucination, confabulation | Переконливий вміст без підтвердження |
| Опора на джерела — grounding | Перевірюваний зв’язок тверджень із наданими матеріалами та посиланнями |
| Захисний механізм — guardrail | Перевірка або обмеження даних навколо моделі |
| Імітація атак — red teaming | Цілеспрямовані спроби виявити шкідливу чи небезпечну поведінку |
| Ін’єкція інструкцій — prompt injection | Спроба змусити модель виконати інструкції нападника замість дозволених |
| Порівняльний тест — benchmark | Стандартизоване оцінювання для зіставлення моделей |
| pass@k / pass^k | Імовірність успіху хоча б однієї з k спроб / усіх k спроб |

## Як вибрати найпростіше рішення

Для запитання про повернення товару потрібні актуальні правила магазину. RAG знаходить матеріал; інструмент за потреби перевіряє замовлення, до якого має доступ користувач; LLM пояснює результат із посиланнями. Перетворення CSV на JSON краще виконати детермінованим парсером. Для узагальнення різних звернень генерація може бути корисною, але конфіденційність і формат залишаються важливими.

Архітектуру визначають коректність, актуальність, конфіденційність, затримка, вартість та складність експлуатації. Тестування допомагає досягти цих цілей.

## Типові помилки

- Вважати кожну систему AI чатботом, а кожну нейромережу — LLM.
- Сприймати згенерований текст як перевірений факт.
- Очікувати, що модель сама забезпечить права доступу або виконає зовнішню дію.
- Використовувати агента там, де достатньо скрипту, пошуку чи одного виклику моделі.
- Вибирати фреймворк і постачальника до визначення завдання та меж системи.

## Підсумок

- Генеративний AI створює вміст; LLM — одна із сімей генеративних моделей.
- Модель, застосунок і продукт мають різні обов’язки.
- Токени, контекст, векторні подання, RAG та інструменти виконують різні завдання.
- Спочатку вивчаємо основи й архітектуру, потім оцінювання, тестування та експлуатацію.
