# Щоденні workflows Claude Code

Кожен крок має давати перевірний результат: контекст, рішення, зміну або evidence.

## Explore, plan, code, commit

Вивчіть реальну реалізацію, залежності й tests. Сплануйте відповідно до ризику, внесіть сумісну зміну, перевірте й перегляньте diff. Не використовуйте формальний план як заміну аналізу або обов’язковий ритуал для кожної дрібниці.

## Керування контекстом

Context показує використання, compact стискає історію, clear змінює початок розмови. Збережіть exact-facts, pointers, failing-case й результати; summary може втратити деталі. Persisted state відрізняється від доступного контексту.

## Code-review

Дайте reviewer вимогу, diff і незалежні очікування, попросіть лише відтворювані issues. Свіжий контекст може зменшити anchoring, але не усуває потребу в tests та source-reading.

## QA-приклад

Згенеровані тести можуть повторити хибний код. Для discount виведіть 0/5/10/20% незалежно, перевірте 99/100 і negative input. Зелений тест без правильного assertion не є evidence якості.

## Обмежена debugging-задача

Відтворіть true/100→10 замість 20, додайте відсутній boundary-case, виправте comparator й перевірте dependent behavior. Після compaction перечитайте базис, а не довіряйте лише переказу. Збережіть точний command і результат.
