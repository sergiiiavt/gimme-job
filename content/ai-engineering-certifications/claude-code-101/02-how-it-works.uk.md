# Як працює Claude Code

Coding-agent читає контекст, виконує дозволені дії та перевіряє наслідки. Tool-return сам не доводить бажану поведінку.

## Цикл у проєкті

Agent збирає факти, пропонує наступну дію, виконує tools і реагує на результат. Runtime задає permissions, budgets і state. Generated-code має пройти незалежні checks; агент може помилково повторити припущення поточної реалізації.

## Де працює

CLI, IDE та інші підтримувані surfaces відрізняються. Local-filesystem не означає необмежених прав; remote/connectors мають власну авторизацію. Перевіряйте актуальний client-contract.

## Permission modes

Default, acceptEdits і plan мають різні призначення; додаткові modes залежать від availability. Plan підтримує read/explore й планування. Не плутайте mode, sandbox і backend-access-control.

## Перший prompt

Попросіть пояснити релевантну функцію, вимогу та тести до edit. Задайте scope, expected behavior та команди перевірки. Не давайте неоднозначне «виправ усе» без визначення об’єкта й oracle.

## Дослідження перед дією

Для discount спочатку виведіть чотири правила й очікування на 99/100, перевірте working tree. Потім мінімальний edit і тести. Велика нечітка зміна потребує плану; зрозуміла boundary-правка може бути виконана прямо після перевірки факту.
