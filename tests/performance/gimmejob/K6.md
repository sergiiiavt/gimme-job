# GimmeJob k6 load test

`k6.js` is the k6 implementation of the same authorized read-only workload defined in `locustfile.py`.
It is intentionally a protocol-level test: k6 sends the HTTP requests that the public UI uses, but it does not launch a browser or execute React, CSS, images, or browser JavaScript.

## Workload parity with Locust

| Selector | Request flow | Locust equivalent |
| --- | --- | --- |
| `full-readonly` | Weighted mix of all read-only tasks | `LOCUST_TAGS=full-readonly` |
| `vacancies-ui` | `GET /vacancies` -> `GET /api/auth-state` -> `GET /api/dashboard` | `LOCUST_TAGS=vacancies-ui` |
| `health` / `smoke` | `GET /api/health` | `LOCUST_TAGS=health` / `smoke` |
| `home` | `GET /` | `LOCUST_TAGS=home` |
| `reference` | `GET /reference/qa-fundamentals` | `LOCUST_TAGS=reference` |
| `jobs-api` / `infra` | `GET /api/public/jobs` | `LOCUST_TAGS=jobs-api` / `infra` |
| `dashboard` | standalone `GET /api/dashboard` | `LOCUST_TAGS=dashboard` |

The `full-readonly` task weights are the same as Locust:

- `vacancies-ui`: weight 6;
- `health`: weight 1;
- `home`: weight 1;
- `reference`: weight 1;
- `jobs-api`: weight 1;
- `dashboard`: weight 1.

The Vacancies scenario is one user action composed of three requests. The anonymous `GET /api/auth-state` response is expected to be HTTP `401`; k6 marks that status as expected for that request instead of counting it as an HTTP failure.

## Load model

The k6 script uses a `ramping-vus` executor.

Configuration is controlled by environment variables:

| Name | Local default | Production default | Meaning |
| --- | ---: | ---: | --- |
| `GIMMEJOB_HOST` | `http://127.0.0.1:4173` | must be set for production | Target base URL |
| `GIMMEJOB_SCENARIO` | `full-readonly` | `vacancies-ui` when omitted | Workload selector |
| `GIMMEJOB_USERS` | `1` | `10` | Target virtual users |
| `GIMMEJOB_SPAWN_RATE` | `1` | `1` | VUs added per second while ramping |
| `GIMMEJOB_DURATION` | `30s` | `10m` | Total scenario duration including ramp-up |

For example, `10` users with spawn rate `1` creates a 10-second ramp from 0 to 10 VUs. The remaining configured duration holds 10 VUs. Each VU waits a random 2-5 seconds after completing one selected task, matching Locust's `between(2, 5)` behavior.

## Install k6

Use the official k6 installation method for your platform. The workload is written for current Grafana k6 and is validated as normal JavaScript in repository CI.

Windows examples:

```powershell
winget install k6 --source winget
```

or use Docker:

```powershell
docker pull grafana/k6
```

## Local smoke

Start GimmeJob locally, then run:

```powershell
k6 run `
  -e GIMMEJOB_HOST=http://127.0.0.1:4173 `
  -e GIMMEJOB_SCENARIO=health `
  -e GIMMEJOB_USERS=1 `
  -e GIMMEJOB_SPAWN_RATE=1 `
  -e GIMMEJOB_DURATION=30s `
  tests/performance/gimmejob/k6.js
```

## Production Vacancies scenario

Production is protected by an explicit acknowledgement, HTTPS enforcement, user cap, and duration cap:

```powershell
k6 run `
  -e GIMMEJOB_HOST=https://gimme-job.com `
  -e GIMMEJOB_PRODUCTION_ACK=gimme-job.com `
  -e GIMMEJOB_SCENARIO=vacancies-ui `
  -e GIMMEJOB_USERS=10 `
  -e GIMMEJOB_SPAWN_RATE=1 `
  -e GIMMEJOB_DURATION=10m `
  tests/performance/gimmejob/k6.js
```

If `GIMMEJOB_SCENARIO` is omitted for production, the script deliberately defaults to `vacancies-ui` rather than broadening the run to every diagnostic endpoint.

## Production full-readonly baseline

This is the direct k6 counterpart of the saved Locust/Azure `full-readonly` baseline:

```powershell
k6 run `
  -e GIMMEJOB_HOST=https://gimme-job.com `
  -e GIMMEJOB_PRODUCTION_ACK=gimme-job.com `
  -e GIMMEJOB_SCENARIO=full-readonly `
  -e GIMMEJOB_USERS=10 `
  -e GIMMEJOB_SPAWN_RATE=1 `
  -e GIMMEJOB_DURATION=10m `
  tests/performance/gimmejob/k6.js
```

To run the 50- or 100-user comparison matrix, explicitly raise `GIMMEJOB_MAX_USERS`; the script otherwise caps production at 10 users:

```powershell
-e GIMMEJOB_MAX_USERS=100
```

The production duration cap is 600 seconds by default. Raising it also requires an explicit environment variable:

```powershell
-e GIMMEJOB_MAX_RUN_SECONDS=1200
```

The safety guard reads k6's consolidated runtime options through `k6/execution`, so CLI execution overrides cannot silently bypass the configured production user/duration caps.

## Result semantics

The script maintains a custom `gimmejob_request_failed` rate. Unlike raw `http_req_failed`, it also counts a response as failed when the HTTP status is technically successful but the GimmeJob response contract is wrong, for example:

- `/api/health` is not valid JSON;
- `ok !== true`;
- the dashboard response has no `jobs` array;
- the expected HTML marker is missing.

At the end of a local k6 run, the summary reports:

- request count and RPS;
- request failure ratio;
- p50, p90, p95, and p99 response time;
- whether the exploratory reporting levels were exceeded.

The default reporting levels match the Locust project:

- failure ratio > 1%;
- aggregate p95 > 10000 ms.

These are **performance findings**, not k6 thresholds. The script intentionally does not define k6 `thresholds`, because a slow or error-heavy application run should still be distinguishable from a test that failed to execute. Invalid configuration and production-safety violations abort the run; high p95 or failure ratio are reported as warnings.

Override the reporting levels when needed:

```powershell
-e GIMMEJOB_MAX_FAILURE_RATIO=0.01 `
-e GIMMEJOB_MAX_P95_MS=10000
```

## Locust-to-k6 concept mapping

| Locust | k6 |
| --- | --- |
| `HttpUser` | VU executing `default()` |
| `@task(weight)` | weighted task selection in `full-readonly` |
| `@tag(...)` / `--tags` | `GIMMEJOB_SCENARIO` selector |
| `between(2, 5)` | `sleep(2 + Math.random() * 3)` |
| `self.client.get(...)` | `http.get(...)` |
| `catch_response=True` + `response.failure(...)` | response validation + `gimmejob_request_failed` custom `Rate` |
| expected anonymous `401` | per-request `http.expectedStatuses(401)` callback |
| `--users` | `GIMMEJOB_USERS` |
| `--spawn-rate` | `GIMMEJOB_SPAWN_RATE` converted into ramp duration |
| `--run-time` | `GIMMEJOB_DURATION` |
| quitting listener | `handleSummary(data)` |

The goal is not to make the source look identical. The goal is to express the same user behavior, request contracts, load shape, safety constraints, and result interpretation using native k6 concepts.
